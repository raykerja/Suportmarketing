# Template workflow n8n

File `*.template.json` adalah salinan portabel dari alur riset target, surat teks ke Drive, kunjungan ke Sheet, dan **draft generator penawaran website**. Seluruh **credential binding**, `webhookId`, dan nilai `X-RAY-Secret` asli telah dihapus/diganti placeholder. ID spreadsheet pada template kunjungan juga diganti `SET_SPREADSHEET_ID`.

`offer-documents.template.json` adalah template workflow web yang **sudah aktif di produksi** setelah konfigurasi credential dan ID. Webhook `raykerja-offer` menerima data dari Edge Function setelah target disetujui dan UMK diisi. Workflow menyalin template RAB dan Google Docs, mengisi sel `A4`, `B10`, `G10`, `J36` pada RAB serta placeholder surat, memindahkan kedua salinan ke folder Drive akun, lalu callback ke Supabase. Ganti `SET_RAB_TEMPLATE_ID` dengan ID draf RAB yang telah dinilai, `SET_DOC_TEMPLATE_ID` dengan ID template surat, `SET_COUNTER_SHEET_ID` dengan ID counter nomor surat, dan `SET_MARKETING_WEBHOOK_SECRET` dengan secret yang sama pada Edge Function. Pilih ulang credential Google Sheets, Google Drive, Google Docs, dan HTTP Request Google Sheets; periksa setiap node sebelum aktivasi.

Workflow Telegram `RAY - Generator Dokumen Penawaran` tetap independen. Keduanya memakai counter nomor surat yang sama; bila dua permintaan dijalankan hampir bersamaan, nomor dapat berbenturan karena Sheet tidak menyediakan increment atomik pada pola ini. Periksa nomor surat saat uji produksi dan pertimbangkan satu layanan penomoran transaksi untuk semua kanal sebelum volume meningkat. Bila counter tahun berjalan belum memiliki baris, workflow web berhenti sebelum menyalin dokumen; tambahkan baris tahun sesuai prosedur administrasi penomoran sebelum pergantian tahun.

Untuk lingkungan baru: impor template sebagai workflow **nonaktif**, pilih ulang credential OpenAI/Google Search/Google Drive/Google Sheets pada node yang memerlukannya, isi ID Sheet dan secret webhook yang sama dengan Edge Function, periksa semua URL callback dan path webhook, lalu uji end-to-end sebelum aktivasi. Jangan aktifkan template mentah; placeholder belum terkonfigurasi.

Workflow production saat ini sudah aktif dengan ID pada `PROJECT_HANDOFF.md`. Template ini merupakan bahan pemulihan/migrasi, bukan backup credential atau export execution history. Script `scripts/export_portable_workflows.py` dapat membuat ulang template dari draft privat bila draft tersebut tersedia secara lokal.

## Revisi pencarian RUP pemerintah (2026-10-04)

`target-research.template.json` memakai `sirup_search` langsung ke endpoint publik SiRUP/INAPROC. Permintaan harus menyertakan parameter DataTables lengkap (`columns[1..11][data]`, `draw`, `start`, `length`, `order`, `search[value]`) dan header `User-Agent`, `X-Requested-With`, `Accept`, `Referer`; tanpa ini server dapat mengembalikan 403 atau HTTP 200 dengan isi kosong. Tahun anggaran dihitung `tahun riset - 1`. `sirup_detail` membaca halaman resmi paket untuk T.A., pagu, volume, uraian, dan spesifikasi. `rup_document_search` memakai credential Serper sebagai cadangan untuk ekspor RUP/SiRUP di domain `go.id`. Workflow aktif sudah diperbarui; webhook, Drive, dan callback lama tetap digunakan. **Uji dari server n8n menunjukkan HTTP 403 pada `sirup_search`**, sehingga pagu/personel belum otomatis terisi. Endpoint yang sama berhasil dari komputer lokal dengan paket TA 2025, tetapi akses dari IP n8n dan Supabase Edge ditolak. Fallback dokumen resmi belum menemukan paket yang cocok pada tiga uji.

Untuk riset tahun 2026, cari **TA 2025** sebagai pembanding. Tahun pemilihan pada baris RUP dapat berbeda dari tahun anggaran. Pagu adalah rencana tahun lalu; jumlah personel perlu bukti eksplisit di paket/KAK/RKS. Jika dokumen tidak ditemukan atau tidak menuliskan jumlah, tampilkan `Belum ditemukan`/`Belum terverifikasi`, jangan menghitung personel dari pagu. Jangan menandai pembacaan SiRUP production PASS sampai jaringan server diizinkan dan satu hasil riset cocok dengan dokumen aslinya.
